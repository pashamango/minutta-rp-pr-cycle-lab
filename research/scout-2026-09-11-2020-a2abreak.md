# Research Scout — A2ABreak / A2A protocol security

Date: 2026-09-11
Status: evidence update; no execution authorization

## Finding

A2ABreak (arXiv:2609.10871, submitted 2026-09-09) reports the first systematic specification-level security analysis of A2A. The authors extract 929 normative statements into a verified 37-state / 76-transition finite-state machine and report 11 protocol-level vulnerabilities exploitable by a specification-compliant adversary. Representative gaps: unbound conversation context IDs enabling cross-client context injection; hop-by-hop identity that loses the original principal across delegation chains; and self-asserted AgentSkill/capability claims without protocol-level attestation.

Primary source: https://arxiv.org/abs/2609.10871
Reproducibility repo: https://github.com/arlotfi79/A2ABreak (MIT, Python; public repo created 2026-09-08).

## Decision relevance

This materially changes how A2A should be treated in our sovereign-worker path (#108). A2A can remain a transport/interoperability surface, but its protocol objects must not be accepted as sufficient evidence of authority, provenance, capability, or delegation identity. The existing #108 boundary is directionally correct; the paper gives concrete adversarial cases to add to acceptance testing rather than creating a new execution lane.

Recommended additions to #108 tests:

1. Bind every context/task namespace to the authenticated principal; reject cross-principal context reuse/injection.
2. Preserve and verify original-principal/delegation-chain identity separately from hop transport auth; never forward reusable credentials through opaque intermediaries.
3. Treat capability cards / AgentSkill declarations as untrusted discovery hints until independently attested or locally verified.
4. Keep authority/mandate/action-binding checks outside A2A; fail closed when that evidence is missing.
5. Where practical, derive a small explicit state machine for the tested lifecycle and adversarially exercise every state transition rather than relying on prompt-level expectations.
